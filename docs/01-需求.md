# 医院 IT 运维平台 · 需求说明 v0.1


---

## 1. 一句话定位

给医院信息科用的一套报修台账工具——设备坏了，报修人在网页上提一张单子，信息科分派、维修、回访，全程留痕，不用再靠打电话和在群里喊。

**它不是**：不是 HIS、不是监控系统、也不给病人用；只服务医院内部信息科，数据全是模拟的。


---

## 2. 角色（谁在用）

| 角色 | 他在系统里干什么 | 大概多久用一次 |
|---|---|---|  
| 报修人（科室护士/医生、自助机引导员） | 发现设备坏了，提一张工单；之后能看进度、能催 | 一周1-2次 |
| 信息科工单审核 | 判断该不该修、派给谁、跟踪期到了关单 | 每天 |
| 运维工程师（处理人） | 接单、去修、填处理说明、提交“已解决” | 每天 3–10 次 |


---

## 3. 核心流程：一张工单的一生

### 3.1 状态列表（只写你 v0.2 真的要实现的）

- [待受理]
- [处理中]
- [已解决]
- [已关闭]
- [后续跟踪]
- [已撤销]
- [已拒绝]
### 3.2 状态流转表（今天最重要的表）

| 从 | 到 | 谁触发 | 什么条件下才允许 |
|---|---|---|---|
| 待受理 | 处理中 | 工单审核 | 指定处理人并且经该处理人确认 |
| 待受理 | 已撤销 | 报修人 | 本人撤回，且工单尚未被受理 |
| 处理中 | 已解决 | 运维工程师 | 只有运维工程师能提交，且填了处理说明 |
| 处理中 | 已拒绝 | 工单审核 | 判定不属于信息科职责范围，必须填理由 |
| 已解决 | 后续跟踪 | 工单审核 | 工单审核确定运维工程师提交的完成报告后，使工单进入后续跟踪 |
| 后续跟踪 | 处理中 |工单审核|发现申报人在后续跟踪阶段提出的问题，重新进入处理中，原运维工程师继续处理|
| 后续跟踪 | 已关闭 | 工单审核 | 跟踪期过后，问题不再复发且发起人满意 |

## 4. 边界与例外

每条用一句话回答。答不上来就写 `?待确认`，并记到第 8 节的访谈清单里。

1. 工单还没指定处理人，能不能直接点"已解决"？
   → 【你的答案】不能。没认领就解决，系统要拦住。
2. 同一台设备 5 分钟内报了 3 次同样的故障，应该生成 3 张工单还是 1 张？
   → 【你的答案】生成一张并标出重复报错次数。
3. 处理人离职/被删了，他手上的工单怎么办？
   → 【你的答案】工单审核判断后继续派出工单，毕竟工单维修是为了维护整个系统。
4. 资产已经"报废"了，还能不能给它建新工单？
   → 【你的答案】不能，已经报废就没必要继续维护了
5. 工单关闭后，报修人说没修好，是重开原来那张，还是新建一张？
   → 【你的答案，并说明为什么】在我的体系中解决后会进入后续追踪期，确认一段时间无误后才会关闭，如果关闭后又出现错误，应该算作一个新的工单
6. 两个运维同时点"接单"，谁抢到？
   → 【你的答案】UPDATE work_order
                 SET status = '处理中', handler_id = ?, accept_time = NOW()  -- 把状态改成处理中，并写上是谁接的单
                 WHERE id = ?                -- 限定是这一张单子
                 AND status = '待受理'     -- 【关键1】只有在“待受理”状态下才能改
                 AND handler_id IS NULL;   -- 【关键2】只有“还没人接”的情况下才能改
   两个请求同时进来，MySQL 的行锁会让它们排队，后到的那条 WHERE 条件已经不成立，更新 0 行。

## 5. 数据字段

### 5.1 `asset`（资产台账，v0.1 就做这个）

已定字段：`id / asset_code / name / category / dept / location / critical_level / status / owner / created_at / updated_at`

**补 2 个字段**（想一想信息科真正会关心的信息）：

- last_maintained_on 上一次维修的日期
- next_maintenance_on 下一次需要定期维护的日期

### 5.2 `work_order`（工单，v0.2 做）

勾出最少需要的字段，然后补 2 个：

- [*] 工单编号
- [ ] 标题
- [*] 故障描述
- [*] 优先级（高/中/低）
- [*] 关联资产 id
- [*] 报修人
- [*] 处理人
- [*] 当前状态
- [*] 创建时间
- [] 解决时间 `不是必填必须要可空`
- [ ] 处理满意度
- [ ] 维修消耗
