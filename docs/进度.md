## 六、关键决策记录（面试会问"为什么"）

1. **为什么用 Spring Boot 4 而不是 3.x**：新建项目没有历史包袱，MyBatis-Plus 3.5.18 已支持 Boot 4（`mybatis-plus-spring-boot4-starter`），springdoc 3.x 也已适配。
2. **为什么接收请求用 DTO 而不是直接用 `Asset`**：`id` / `createdAt` / `updatedAt` 是数据库生成的，直接用 Entity 接请求会让别人能传 `"id": 1` 覆盖数据。
3. **为什么必须配 `PaginationInnerInterceptor`**：不配时 `selectPage` 是"假分页"——把全表查出来在内存里截取，数据量一大就崩。配了才是 SQL 层 `LIMIT`。
4. **为什么 `status` 要加 `SCRAPPED`**：需求边界写明"报废资产不能建单"，报废是资产的状态，不是工单的状态。
5. **为什么日期用 `LocalDate` / `LocalDateTime` 而不是 `java.util.Date`**：`Date` 可变、月份从 0 开始、时区处理混乱。
6. **为什么 `asset_code` 加 UNIQUE**：业务上资产编号是唯一标识，重复了就是脏数据。
7. **为什么开 `fail-on-unknown-properties`**：Jackson 默认"不认识就跳过"，字段名拼错会静默丢数据（`loaction` 事故）。开发阶段开着，拼错立刻 400。
8. **为什么数据库密码走环境变量**：仓库将来要公开给人看，明文密码是硬伤；改密码后 git 历史里的旧值也失效了。
9. **为什么 Create 和 Update 用两个 DTO**：`assetCode` 是业务主键（贴在机箱上的编号），更新时不允许改，所以 `AssetUpdateRequest` 里干脆没有这个字段；配合严格模式，传了就 400。
10. **为什么 PUT 表现为"部分更新"**：MyBatis-Plus 的 `updateById` 默认忽略 null 字段（字段策略 `NOT_NULL`），所以没传的字段保持原值。**这是已知行为，不是 bug**；要清空某字段得改用 `UpdateWrapper.set()`。README 里写清楚。
11. **为什么 DELETE 现在是物理删除**：v0.1 求简单。**已知局限**：真实运维系统不物理删除资产，因为历史工单、审计日志会引用它。v0.2 改逻辑删除（`deleted` 字段 + `@TableLogic`）。

## 七、踩过的坑（避免重复踩）

- **`@MapperScan` 漏了**：Mapper 接口找不到，启动报 `NoSuchBeanDefinitionException`。
- **MySQL 时区报错**：URL 里必须带 `serverTimezone=Asia/Shanghai`。
- **下划线转驼峰**：`application.yml` 里必须有 `map-underscore-to-camel-case: true`，否则返回的字段是 `asset_code`。
- **产出物必须放在仓库根目录内**：`docs/`、`sql/` 一度放在仓库外，`git add` 根本收不进去，commit 里是空的。
- **DTO 少 `@Data`**：Jackson 写不进字段，全部为 null，被 `@Valid` 拦成 400。排查花了很久。
- **`BeanUtils.copyProperties` 静默失败**：字段名拼错（`loaction`）/ 类型不匹配都不报错，只把 null 写进库。靠 `SELECT` 才发现。
- **敏感配置别进仓库**：数据库密码一度被提交，已改为 `${DB_PASSWORD:}` 并换掉了 root 密码。
- **IDEA 自动导入会塞垃圾 import**：`JdbcClient`、`RegularEscapeUtil`、`ApplicationEventPublisher` 都是这么进来的，编译不报错但属于死代码，提交前扫一眼 import 区。
- **异常类型会漏**：`@Valid` 抛 `MethodArgumentNotValidException`，但 `@RequestParam` 上的 `@Min/@Max` 抛 `HandlerMethodValidationException`，`?page=abc` 抛 `MethodArgumentTypeMismatchException`。漏一个就会把 400 报成 500。
